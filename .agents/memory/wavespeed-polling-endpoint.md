## Poll endpoint (all models)

```
GET https://api.wavespeed.ai/api/v3/predictions/{task-id}/result
```

**Not** `/api/v3/outputs/` and **not** `/api/v3/status/` — both return 404.

## outputs shape

`result.outputs` is a **plain `string[]`** (CloudFront URLs), not `{ images: [] }`.  
Handle both:

```ts
if (Array.isArray(outputs)) {
  rawUrl = typeof outputs[0] === "string" ? outputs[0] : outputs[0]?.url;
} else { /* object fallback */ }
```

## Voice-clone API contract (minimax/voice-clone)

Endpoint: `POST /api/v3/minimax/voice-clone`  
Content-Type: `application/json` — **NOT** multipart/form-data.  
`audio` field must be a **URL**, not a binary blob.

```json
{
  "audio": "<publicly accessible URL>",
  "custom_voice_id": "WsV<timestamp><hex6>",
  "model": "speech-02-hd",
  "language_boost": "Spanish",
  "need_noise_reduction": true,
  "need_volume_normalization": true,
  "accuracy": 0.7
}
```

### custom_voice_id rules
- ≥ 8 characters
- Must start with a letter
- Must contain both letters and numbers
- Must be unique per WaveSpeed account (duplicate = error)
- **Generated by us before submission** — save to DB immediately; no need to parse from outputs

### Lifecycle simplification
Since we set `custom_voice_id` ourselves, `wavespeedVoiceId` can be stored at insert time.
Polling only needs to flip `status → "ready"` on completion; no output parsing needed.

**Why:** The voice ID IS the `custom_voice_id` we provided — WaveSpeed doesn't assign a new one.

**How to apply:** In the route handler, generate `WsV${Date.now()}${hex6}` before calling `submitVoiceClone`, insert it as `wavespeedVoiceId` immediately, then in the poll just `SET status='ready'`.
