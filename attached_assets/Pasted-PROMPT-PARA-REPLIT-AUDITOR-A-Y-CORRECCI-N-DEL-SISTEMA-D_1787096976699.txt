PROMPT PARA REPLIT — AUDITORÍA Y CORRECCIÓN DEL SISTEMA DE CRÉDITOS

Quiero que revises y corrijas completamente el sistema de créditos de Reelsona. Actualmente la app no está descontando créditos correctamente en producción.

No quiero que crees un wallet nuevo. Ya existe un sistema de créditos con availableCredits, subscriptionCredits, purchasedCredits, reservedCredits, totalConsumed y credit_ledger. Debes usar y estabilizar ese sistema existente.

FLUJO CORRECTO PARA VIDEO

Debe utilizarse el sistema existente:

Antes de enviar el job al proveedor

calcular créditos
comprobar saldo
ejecutar reserveCredits()

El usuario debe ver inmediatamente reducido su saldo disponible.

Si el video termina correctamente

ejecutar consumeVideoCredits()
mover la reserva a consumo definitivo

Si el video falla, timeout, API error o cancelación

ejecutar releaseVideoCredits()
devolver exactamente los créditos reservados

Nunca dejar créditos bloqueados.

Nunca cobrar dos veces el mismo video.

IDEMPOTENCIA

Esta parte es crítica.

Si:

el webhook llega dos veces
el scheduler procesa dos veces
el usuario refresca
el frontend reintenta una request
una callback se ejecuta nuevamente

NO se pueden volver a descontar créditos.

Cada operación facturable debe tener una referencia única en credit_ledger.

Antes de descontar, comprobar si la misma operación ya fue reservada/consumida.

LOOKS

Revisar cómo identifica Reelsona cuáles son los 3 looks iniciales gratuitos.

No asumir simplemente “los primeros 3 registros” si eso puede romperse con reintentos.

Debe quedar una forma persistente de saber:

look incluido/gratuito
look adicional/facturable

Para un look adicional:

comprobar saldo ≥ 2
reservar/descontar 2 créditos
llamar al proveedor
si falla, devolver 2
si funciona, registrar consumo en ledger
VOZ

Revisar cómo se identifica la primera voz gratuita.

La primera voz clonada debe costar 0.

Segunda voz en adelante:

10 créditos cada una

Debe quedar persistido en DB que el usuario ya usó su clon gratuito.

Si la clonación falla, los 10 créditos deben regresar.

B-ROLL

Si un Reel genera 3 imágenes AI para B-roll:

3 × 2 = 6 créditos

Cobrar solo las imágenes que realmente se envían al proveedor.

Si una imagen falla:

no cobrarla definitivamente
devolver su reserva

No cobrar B-roll si simplemente se reutiliza un asset existente.
